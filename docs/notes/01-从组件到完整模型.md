## 1. 全景：三层嵌套

MiniMind 的代码结构是三层嵌套，每一层只做一件事：

```
MiniMindForCausalLM                    ← 语言模型外壳：输出词表概率、算 loss、生成文本
├── model: MiniMindModel               ← 主干：把 token 序列变成上下文相关的向量
│   ├── embed_tokens  (6400 → 768)     ← 入口：token id → 向量
│   ├── freqs_cos / freqs_sin          ← RoPE 角度表（buffer，无参数）
│   ├── layers: 8 × MiniMindBlock      ← 核心：堆叠的 Transformer Block
│   │   ├── input_layernorm            ← RMSNorm
│   │   ├── self_attn: Attention       ← 注意力（内含 QK-Norm、RoPE、GQA、因果掩码）
│   │   ├── post_attention_layernorm   ← RMSNorm
│   │   └── mlp: FeedForward / MOE     ← FFN（SwiGLU）或 MoE
│   └── norm                           ← 最终 RMSNorm
└── lm_head  (768 → 6400)              ← 出口：向量 → 词表 logits（与 embed_tokens 共享权重）
```

数据流一句话概括：

$$
\text{token ids}\xrightarrow{\text{Embedding}} x_0 \xrightarrow{\text{Block}_1}\ x_1 \xrightarrow{\text{Block}_2}\cdots\xrightarrow{\text{Block}_8} x_8 \xrightarrow{\text{RMSNorm}}\xrightarrow{\text{lm\_head}}\text{logits}
$$

这种分层是 HuggingFace 生态的惯例（LLaMA、Qwen 都是 `XxxModel` + `XxxForCausalLM`）：同一个主干 `MiniMindModel` 可以接不同的"头"，做语言建模、分类或者奖励模型。

## 2. 配置：一张表定下所有尺寸

`MiniMindConfig`（`model/model_minimind.py:10-45`）决定了所有组件的尺寸。默认值：

| 参数 | 默认值 | 作用于 | 含义 |
|---|---|---|---|
| `vocab_size` | 6400 | Embedding、lm_head | 词表大小 |
| `hidden_size` | 768 | 全局 | 残差流宽度，所有组件的"接口宽度" |
| `num_hidden_layers` | 8 | 主干 | Block 个数 |
| `num_attention_heads` | 8 | Attention | Q 头数 |
| `num_key_value_heads` | 4 | Attention | K/V 头数（GQA，每 2 个 Q 头共享 1 组 KV） |
| `head_dim` | 768 / 8 = 96 | Attention、RoPE | 每个头的维度，也是 RoPE 旋转的维度 |
| `intermediate_size` | ⌈768·π / 64⌉·64 = 2432 | FFN | FFN 中间层宽度 |
| `hidden_act` | silu | FFN | SwiGLU 中门控的激活函数 |
| `rms_norm_eps` | 1e-6 | RMSNorm | 防止除零 |
| `rope_theta` | 1e6 | RoPE | 旋转频率的底数 |
| `max_position_embeddings` | 32768 | RoPE | 预计算多少个位置的角度 |
| `tie_word_embeddings` | True | Embedding、lm_head | 输入输出共享权重 |
| `use_moe` | False | FFN | 是否把 FFN 换成 MoE |

**最重要的约束：`hidden_size` 贯穿全模型。** 每个组件都是"768 进、768 出"，内部可以随意变宽变窄（注意力拆成 8×96，FFN 扩到 2432），但出口必须回到 768。这是残差相加（`x + F(x)`）能成立的前提，也是 Block 能任意堆叠的前提。

## 3. 入口：Embedding

```python
self.embed_tokens = nn.Embedding(config.vocab_size, config.hidden_size)   # :206
hidden_states = self.dropout(self.embed_tokens(input_ids))                 # :219
```

`nn.Embedding` 本质是一张 6400 × 768 的表，第 $i$ 行就是第 $i$ 个 token 的向量。输入 `[B, T]` 的整数 id，查表得到 `[B, T, 768]`。

两点值得注意：

- **这里不加位置编码。** 原始 Transformer 在这一步做 `embedding + PE`；MiniMind 的 embedding 是纯语义的，位置信息交给每层注意力里的 RoPE。
- **初始化很小。** 实测第 0 层输入的向量范数约 0.556（见第 6 节表格），约等于 $\sqrt{768}\times 0.02$，也就是每个分量的标准差为 0.02。

## 4. 位置信息：RoPE 只算一次，层层共享

RoPE 不属于任何一个 Block，而是由 `MiniMindModel` 统一管理：

```python
# __init__：预计算 32768 个位置 × 96 维的 cos/sin 表，只算一次        :210-212
freqs_cos, freqs_sin = precompute_freqs_cis(dim=config.head_dim, end=config.max_position_embeddings, ...)
self.register_buffer("freqs_cos", freqs_cos, persistent=False)
self.register_buffer("freqs_sin", freqs_sin, persistent=False)

# forward：按当前位置切出需要的那一段，传给每一层                       :218, :224
start_pos = past_key_values[0][0].shape[1] if past_key_values[0] is not None else 0
position_embeddings = (self.freqs_cos[start_pos:start_pos + seq_length],
                       self.freqs_sin[start_pos:start_pos + seq_length])
```

设计要点：

| 设计 | 原因 |
|---|---|
| 放在 `MiniMindModel` 而不是 Block 里 | 8 层用的是同一张角度表，没必要存 8 份 |
| `register_buffer` | 会跟着 `.to(device)` 移动到 GPU，但不是参数，不参与训练 |
| `persistent=False` | 不写进权重文件，加载时重新计算（第 221-223 行还有一段兜底重算的逻辑） |
| 用 `start_pos` 切片 | 推理时用了 KV Cache，新 token 的位置 = 已缓存的长度，必须从那里开始取角度 |

每一层的注意力拿到 `(cos, sin)` 后，只对 Q、K 做旋转（`:118-119`）。

## 5. 核心单元：Transformer Block

`MiniMindBlock`（`:183-199`）是整个模型里唯一重复的部分：

```python
class MiniMindBlock(nn.Module):
    def __init__(self, layer_id, config):
        self.self_attn = Attention(config)
        self.input_layernorm = RMSNorm(config.hidden_size, eps=config.rms_norm_eps)
        self.post_attention_layernorm = RMSNorm(config.hidden_size, eps=config.rms_norm_eps)
        self.mlp = FeedForward(config) if not config.use_moe else MOEFeedForward(config)

    def forward(self, hidden_states, position_embeddings, past_key_value=None, use_cache=False, attention_mask=None):
        residual = hidden_states
        hidden_states, present_key_value = self.self_attn(
            self.input_layernorm(hidden_states), position_embeddings,
            past_key_value, use_cache, attention_mask)
        hidden_states += residual                                                          # 子层 1
        hidden_states = hidden_states + self.mlp(self.post_attention_layernorm(hidden_states))  # 子层 2
        return hidden_states, present_key_value
```

写成公式：

$$
\begin{aligned}
h &= x + \text{Attention}\big(\text{RMSNorm}_1(x),\ \text{RoPE}\big) &&\text{子层 1：token 之间交流}\\
x' &= h + \text{FFN}\big(\text{RMSNorm}_2(h)\big) &&\text{子层 2：每个 token 独立加工}
\end{aligned}
$$

两个子层套用同一个模板：**归一化 → 计算 → 加回主干**。

```
          x  [B, T, 768]   ← 残差主干
          │
          ├────────────┐
          │       RMSNorm₁
          │            │
          │       Attention ←── RoPE (cos, sin)
          │            │
          ⊕◄───────────┘
          │
          h
          ├────────────┐
          │       RMSNorm₂
          │            │
          │      FFN (SwiGLU / MoE)
          │            │
          ⊕◄───────────┘
          │
          x' [B, T, 768]   → 下一个 Block
```

### 各组件在 Block 中的位置

| 组件 | 位置 | 原因 |
|---|---|---|
| RMSNorm | 每个子层入口，只在旁路上（Pre-Norm） | 稳定子层输入的尺度；主干不被打断，梯度可沿恒等路径直通 |
| Attention | 第一个子层 | 先汇集上下文，FFN 才有东西可加工 |
| RoPE | 注意力内部，只旋转 Q、K | 位置只影响"看谁"，不污染 V 和主干 |
| QK-Norm | 注意力内部，RoPE 之前（`:117`） | 防止 $q\cdot k$ 过大导致 softmax 饱和 |
| FFN | 第二个子层 | 非线性加工，调取参数中的知识 |
| 残差 ⊕ | 每个子层出口 | 子层只需学"修改量"；梯度高速公路 |

### Block 内部的形状变化（实测，B=2, T=16）

| 步骤 | 输入 | 输出 | 说明 |
|---|---|---|---|
| `input_layernorm` | (2, 16, 768) | (2, 16, 768) | 只调尺度 |
| `q_proj` | (2, 16, 768) | (2, 16, 768) | 之后 view 成 8 头 × 96 |
| `k_proj` / `v_proj` | (2, 16, 768) | (2, 16, **384**) | 4 头 × 96，GQA 让 K/V 只有 Q 的一半 |
| QK-Norm + RoPE | — | 形状不变 | 只改数值 |
| `repeat_kv` | K/V 4 头 | K/V 8 头 | 复制对齐到 Q 的头数 |
| 注意力计算 | — | (2, 8, 16, 96) | $\text{softmax}(QK^\top/\sqrt{96}+\text{mask})\,V$ |
| 拼接 + `o_proj` | (2, 16, 768) | (2, 16, 768) | 各头结果融合回 768 |
| `post_attention_layernorm` | (2, 16, 768) | (2, 16, 768) | |
| `gate_proj` / `up_proj` | (2, 16, 768) | (2, 16, **2432**) | 升维到工作空间 |
| `down_proj` | (2, 16, 2432) | (2, 16, 768) | 降维回接口宽度 |
| Block 输出 | (2, 16, 768) | (2, 16, 768) | **进出形状完全相同** |

## 6. 堆叠：残差流视角

### 6.1 怎么堆

```python
self.layers = nn.ModuleList([MiniMindBlock(l, config) for l in range(self.num_hidden_layers)])   # :208

for layer, past_key_value in zip(self.layers, past_key_values):                                  # :226
    hidden_states, present = layer(hidden_states, position_embeddings, past_key_value=past_key_value, ...)
    presents.append(present)
```

8 个 Block 结构相同但**权重各自独立**，按顺序串联。每层还各自维护一份 KV Cache（`past_key_value`），收集到 `presents` 里返回。

### 6.2 换个角度看：残差流

把 8 层的公式展开：

$$
x_8 = x_0 + \sum_{l=1}^{8}\Big(\text{Attn}_l(\cdots) + \text{FFN}_l(\cdots)\Big)
$$

这提供了一个很好用的理解框架：**残差流（residual stream）是一条贯穿全模型的"总线"**。Embedding 把初始信息写上去，之后每个子层都从总线上**读**（经过 Norm），算完再把结果**加**回总线。没有哪个子层会覆盖总线上的内容，只会累加。

- 注意力的写入：把别的 token 的相关信息搬过来
- FFN 的写入：把参数里记忆的知识加进来
- 最后 lm_head 从总线上读出"下一个词是什么"

### 6.3 实测：每层往总线写了多少

`exp2_model_anatomy.py` 第 3 节记录了每层主干范数，以及注意力、FFN 输出的范数（随机初始化）：

| 层 | 主干输入 | Attn 写入 | FFN 写入 | 主干输出 |
|---|---|---|---|---|
| 0 | 0.556 | 4.597 | 4.571 | 6.550 |
| 1 | 6.550 | 6.130 | 4.574 | 10.048 |
| 2 | 10.048 | 6.942 | 4.702 | 13.287 |
| 3 | 13.287 | 7.497 | 4.566 | 15.877 |
| 4 | 15.877 | 7.645 | 4.614 | 18.026 |
| 5 | 18.026 | 7.558 | 4.540 | 20.085 |
| 6 | 20.085 | 7.280 | 4.528 | 21.869 |
| 7 | 21.869 | 7.796 | 4.579 | 23.743 |

能看出三件事：

1. **主干范数单调增长**（0.56 → 23.7）。因为子层的输入被 RMSNorm 归一化过，每层写入的量大致恒定，而主干只加不减。这就是之前讨论 Pre-LN 时说的"主干范数逐层累积"。
2. **后面的层相对影响越来越小。** 第 0 层写入的量是主干的 8 倍多，第 7 层的写入只有主干的约 1/3。这就是 Pre-LN 的"深层贡献被稀释"问题；层数越多越明显，8 层的 MiniMind 还不严重。
3. **出口必须再归一化一次。** 主干到最后是 23.7，不加处理直接送进 lm_head，logits 的尺度会随层数漂移。这正是下一节最终 Norm 的作用。

（以上是初始化状态。训练之后各层写入的大小会被学习改变，但"只加不减、逐层累积"的结构性质不变。）

## 7. 出口：最终 Norm + lm_head

```python
hidden_states = self.norm(hidden_states)                                       # :235 最终 RMSNorm
logits = self.lm_head(hidden_states[:, slice_indices, :])                      # :253
```

### 7.1 最终 RMSNorm

Pre-LN 结构里，主干从头到尾没有被归一化过（Norm 都在旁路上），所以出口处必须统一做一次，把尺度拉回到稳定范围再送给 lm_head。Post-LN 不需要这一步，因为它每层结束时已经归一化过了。

### 7.2 lm_head 与权重共享

```python
self.lm_head = nn.Linear(self.config.hidden_size, self.config.vocab_size, bias=False)    # :246
if self.config.tie_word_embeddings: self.model.embed_tokens.weight = self.lm_head.weight # :247
```

`lm_head` 是一个 768 → 6400 的线性层，对每个位置输出 6400 个分数（logits）。第 247 行让它和 `embed_tokens` **共用同一个张量**（实验输出 `lm_head 与 embed 是同一个张量: True`）。

为什么可以共享？lm_head 计算的是 $\text{logit}_i = e_i \cdot h$，也就是"最终向量 $h$ 和第 $i$ 个词的嵌入有多像"。输入端"词 → 向量"和输出端"向量 → 词"用同一套词向量，在语义上是自洽的。

好处是省参数：共享省下 6400 × 768 ≈ **4.9M**，在 64M 的模型里接近 8%。大模型词表大但主干更大，共享的收益不明显，所以 LLaMA 等大模型通常不共享；小模型则基本都共享。

### 7.3 `logits_to_keep`：推理时只算最后一个位置

```python
slice_indices = slice(-logits_to_keep, None) if isinstance(logits_to_keep, int) else logits_to_keep   # :252
```

默认 `logits_to_keep=0`，`slice(-0, None)` 即 `slice(0, None)`，保留全部位置（训练需要）。生成时只关心最后一个位置的下一个词，传入 `logits_to_keep=1` 就只对最后一个位置做 768 × 6400 的投影，省下大量计算。

## 8. 训练时：loss 是怎么算的

### 8.1 错位一格的交叉熵

```python
if labels is not None:                                                         # :255-257
    x, y = logits[..., :-1, :].contiguous(), labels[..., 1:].contiguous()
    loss = F.cross_entropy(x.view(-1, x.size(-1)), y.view(-1), ignore_index=-100)
```

语言模型的任务是"用第 $t$ 个位置的输出预测第 $t+1$ 个 token"，所以 logits 去掉最后一个、labels 去掉第一个，正好对齐：

```
输入 tokens:   [我]  [爱]  [北]  [京]
位置输出预测:   爱    北    京    ?     ← 最后一个位置没有答案，丢弃
labels[1:]:    [爱]  [北]  [京]
```

**一次前向就同时训练了 T−1 个预测任务。** 这得益于因果掩码：位置 $t$ 的输出只看得到 $\le t$ 的 token，不会偷看答案（第 5 节的实验验证了这一点）。

### 8.2 `ignore_index=-100`：哪些位置不算 loss

labels 中值为 -100 的位置不参与 loss：
- 预训练：padding 位置被设为 -100（`dataset/lm_dataset.py:57`）
- SFT：用户提问部分也设为 -100，只在助手回答部分算 loss（`generate_labels`，`:91-107`）

### 8.3 MoE 的辅助损失

`MiniMindModel` 还会把所有 MoE 层的 `aux_loss` 加起来返回（`:236`），训练脚本里直接相加：

```python
loss = res.loss + res.aux_loss            # trainer/train_pretrain.py:35
```

不用 MoE 时它恒为 0。

### 8.4 用初始 loss 做健全性检查

随机初始化的模型对每个词"一视同仁"，预测接近均匀分布，交叉熵应接近 $\ln(\text{vocab\_size})$：

```
loss = 9.1373   ln(vocab_size) = ln(6400) = 8.7641
```

实测略高于 $\ln 6400$，因为随机初始化的 logits 不是严格相等，有一定方差（logits 的方差越大，交叉熵越高）。**如果你改了模型结构，训练第一步的 loss 远离这个值（比如几十、上百），通常说明初始化或结构有问题**，这是个很实用的检查手段。

## 9. 推理时：generate 循环与 KV Cache

### 9.1 自回归生成

`MiniMindForCausalLM.generate`（`:262-293`）的核心循环：

```python
for _ in range(max_new_tokens):
    past_len = past_key_values[0][0].shape[1] if past_key_values else 0
    outputs = self.forward(input_ids[:, past_len:], ..., past_key_values, use_cache=True)  # 只喂新 token
    logits = outputs.logits[:, -1, :] / temperature           # 只取最后一个位置
    # repetition_penalty → top_k → top_p 过滤
    next_token = torch.multinomial(torch.softmax(logits, dim=-1), num_samples=1)  # 按概率抽样
    input_ids = torch.cat([input_ids, next_token], dim=-1)    # 拼到序列末尾
    past_key_values = outputs.past_key_values                 # 更新缓存
    if 全部遇到 eos: break
```

每一轮：前向 → 取最后位置的 logits → 调整分布 → 抽一个 token → 拼回输入 → 下一轮。

采样前对 logits 的几道处理：

| 步骤 | 作用 |
|---|---|
| `/ temperature` | 小于 1 让分布更尖锐（更保守），大于 1 更平坦（更随机） |
| `repetition_penalty` | 压低已出现过的 token 的分数，减少复读 |
| `top_k` | 只保留分数最高的 k 个候选 |
| `top_p` | 只保留累计概率达到 p 的最小候选集合 |
| `multinomial` | 按剩余概率随机抽样；`do_sample=False` 时改为取最大值（贪心） |

### 9.2 KV Cache：为什么只需要喂新 token

没有缓存时，生成第 $n$ 个 token 要把前面 $n-1$ 个全部重新算一遍。但在因果注意力下，**旧 token 的 K、V 永远不会改变**（它们看不到后来的 token），所以可以存下来复用：

- 第一轮：输入整个 prompt，每层把 K、V 存进 `past_key_value`
- 之后每轮：只输入 1 个新 token，算出它的 q、k、v；k、v 拼到缓存后面（`:120-122`），q 和全部 K 做注意力

和 RoPE 的配合：K 是**先旋转、再存入缓存**的（`:119` 在 `:121` 之前），新 token 通过 `start_pos` 取到正确的角度，旧 K 不需要重新旋转。

实验第 6 节验证了缓存的正确性：

```
逐 token 增量推理与整句前向的 logits 最大差异: 2.65e-06      ← 只有浮点误差
第 0 层 KV Cache 形状: K (2, 16, 4, 96)  V (2, 16, 4, 96)   [B, 已缓存长度, KV头数, head_dim]
```

缓存里存的是 **4 个 KV 头**，而不是 8 个。这就是 GQA 的意义：KV Cache 的显存占用减半。

### 9.3 因果性验证

实验第 5 节：把位置 10 之后的 token 换掉，

```
位置 0-9 logits 最大差异  0.00e+00     ← 完全不受影响
位置 10-15 logits 最大差异 1.72e+00    ← 正常变化
```

前面位置的输出完全不受后面 token 影响，这正是 8.1 节"一次前向训练 T−1 个任务"和 9.2 节"KV Cache 可以复用"成立的根本原因。

## 10. 参数账本

| 部分 | 参数量 | 占比 |
|---|---|---|
| embed_tokens（= lm_head，共享） | 4.92M | 7.7% |
| Attention × 8 | 14.16M | 22.2% |
| FFN × 8 | 44.83M | 70.1% |
| RMSNorm × 17（每层 2 个 + 最终 1 个） | 13.1K | ≈0 |
| **总计** | **63.91M** | |

单个 Block 的明细：

| 组件 | 计算 | 参数量 |
|---|---|---|
| q_proj | 768 × 768 | 589,824 |
| k_proj | 768 × 384 | 294,912 |
| v_proj | 768 × 384 | 294,912 |
| o_proj | 768 × 768 | 589,824 |
| q_norm / k_norm | 96 + 96 | 192 |
| gate_proj / up_proj | 2 × 768 × 2432 | 3,735,552 |
| down_proj | 2432 × 768 | 1,867,776 |
| 两个 RMSNorm | 2 × 768 | 1,536 |

几个观察：
- **FFN 占 70%**：模型的大部分容量在 FFN 里。
- **GQA 省参数**：如果 K/V 也用 8 头，每层注意力会多 2 × 768 × 384 ≈ 0.59M。
- **RMSNorm 几乎不占参数**，但对训练稳定性至关重要。
- **全模型没有一个 bias**：所有 `nn.Linear` 都是 `bias=False`。

## 12. 小结

> **MiniMind = Embedding + 8 × Block + 最终 Norm + lm_head。**
>
> - 一个宽 768 的**残差流**贯穿全模型，所有组件都是"从总线读、往总线加"。
> - **Block** 是唯一重复的单元：Pre-Norm 的注意力子层负责 token 间交流，Pre-Norm 的 FFN 子层负责逐 token 加工。进出形状相同，所以可以任意堆叠。
> - **RoPE** 只算一次、层层共享，在每层注意力内部旋转 Q、K。
> - **出口**先做最终 Norm（Pre-LN 的主干从未归一化过），再用与 Embedding 共享的 lm_head 打分。
> - **训练**用错位一格的交叉熵，一次前向训练 T−1 个预测；**推理**靠因果性保证 KV Cache 可复用，逐 token 生成。
